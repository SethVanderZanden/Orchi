# Use Visual Cues

## Define the message

1. Name the information, action, state, relationship, or direction the cue must communicate.
2. Decide whether the cue is essential, reinforcing, orienting, or decorative.
3. Prefer familiar conventions when they match the audience and platform.
4. Pair unfamiliar or consequential icons with clear text.

## Select the cue

- Use icons for recognizable objects, actions, or states.
- Use imagery when it conveys context, identity, emotion, or product value better than text.
- Use arrows, lines, position, or motion to show sequence and direction.
- Use badges and indicators for concise status only when their meaning is explicit.
- Use charts and graphics only when they make relationships easier to understand.
- Keep decorative imagery subordinate to task content.

## Make affordances clear

- Give interactive elements visible labels, boundaries, placement, or states appropriate to the platform.
- Keep icon style, stroke, fill, size, and alignment consistent.
- Provide hover, active, selected, focus, loading, and disabled feedback without relying on hover alone.
- Ensure the hit area matches the apparent control.
- Add accessible names and text alternatives according to the cue's purpose.

## Test interpretation

- Test with representative users when symbols may be ambiguous or culturally specific.
- Check grayscale, color-vision variation, zoom, narrow layouts, and missing imagery.
- Verify that essential meaning survives when animation is disabled or images fail.
- Remove cues that repeat information without improving speed or comprehension.

## Avoid these failures

- Do not use decoration as an explanation.
- Do not rely on an icon's popularity within the design team.
- Do not put text inside images when live text can carry the meaning.
- Do not use unlabeled gestures or hover-only discovery for essential actions.
- Do not animate merely to attract attention.

## Produce the result

Return:

1. The message each cue must convey.
2. The selected cue and why it fits.
3. Labeling, alternative text, and interaction-state requirements.
4. Ambiguities and fallback behavior.
5. A consistency checklist for the cue set.
